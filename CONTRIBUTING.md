# Contributing to WebQuake

Thanks for helping to improve WebQuake!

## Issues

Search existing issues before opening a new one, then use the issue template for bug reports, feature requests, and other suggestions. Include enough detail to explain the problem or proposal and how it affects WebQuake.

For bugs, provide steps to reproduce, expected and actual behaviour, and relevant browser, device, language (English/Japanese/Traditional Chinese), and self-hosted setup details (or if you spotted the bug on https://webqua.ke). Screenshots and logs are useful when available. For features, explain the use case and proposed behaviour.

As always, remove credentials, tokens, personal information, and subscriber details from reports, logs, and screenshots.

## Pull requests

For substantial changes, open an issue first to discuss the approach. Keep each PR focused and link any related issues.

Follow the setup instructions in [README.md](README.md). Describe what changed, why, and how you tested it. Include screenshots for visible changes, and check both English and Japanese interfaces where relevant. Document any configuration changes.

**Every PR must be personally verified by the project maintainer, @lukemattle, in WebQuake's dev environment before it can be merged.** This applies to all PRs, including documentation and dependency changes. Contributor testing and automated checks support this review but do not replace it. Access to the dev environment is not required to contribute; the maintainer performs that verification.

Keep credentials out of commits. Preserve the AGPL-3.0 licence, source attribution, and the data attribution and terms listed in [NOTICE](NOTICE).
